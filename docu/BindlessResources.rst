==================
Bindless Resources
==================

XShaderCompiler accepts the Shader Model 6.6 descriptor-heap syntax as the
portable source representation for bindless resources. Enable the
``BindlessResources`` language extension and select HLSL 6 as the input
language.

Input syntax
============

The descriptor heap expression is contextually typed by a local resource
variable. Its index must be a scalar ``uint``. Use
``NonUniformResourceIndex`` when invocations can select different resources::

    cbuffer Params : register(b0)
    {
        uint textureIndex;
        uint samplerIndex;
        float2 texcoord;
    };

    float4 PS() : SV_Target
    {
        Texture2D<float4> textureObject =
            ResourceDescriptorHeap[NonUniformResourceIndex(textureIndex)];
        SamplerState samplerObject =
            SamplerDescriptorHeap[NonUniformResourceIndex(samplerIndex)];
        return textureObject.Sample(samplerObject, texcoord);
    }

The supported resource views are textures and RW textures, typed and RW typed
buffers, structured and RW structured buffers, byte-address and RW
byte-address buffers, and regular or comparison samplers. Append and consume
structured buffers are deliberately excluded because they require counter
metadata that is not represented by a single portable descriptor.

Command line
============

For example, Vulkan GLSL output using descriptor set 2 can be generated with::

    xsc -Vin HLSL6 -Vout VKSL450 -Xbindless ON --extension ON --bindless-set 2 --bindless-slot 4 shader.hlsl

``--bindless-set`` only affects backends whose generated descriptor bindings
have a descriptor-set or register-space component. ``--bindless-slot`` selects
the first slot of the generated bindings, and ``--bindless-layout`` selects
their fixed slots relative to it:

``heap`` (default)
    Two bindings: samplers at the start slot, and every resource class at the
    slot after it. The runtime binding must accept any resource class, e.g.
    ``VK_DESCRIPTOR_TYPE_MUTABLE_EXT`` holding sampled images, texel buffers
    and storage buffers. The resource binding is the higher one, so it can use
    a variable descriptor count if no source binding in the set follows it.

``type``
    One binding per descriptor type, at these offsets from the start slot:
    0 = samplers, 1 = sampled images, 2 = storage images, 3 = uniform texel
    buffers, 4 = storage texel buffers, 5 = storage buffers.

Slots don't depend on which heap views a shader uses, so every shader compiled
with the same set, start slot and layout shares one descriptor layout. Typed
views that map to one slot alias the same descriptors.

The compiler first reserves every explicit source binding, then the bindless
slots, then assigns missing source bindings when automatic binding is enabled.
Automatically assigned source bindings skip the bindless slots. An explicit
source binding on a bindless slot is an error. Bindless slots are independent of
``--auto-bind`` and ``--auto-bind-slot``.

The equivalent library settings are ``Extensions::BindlessResources``,
``Options::bindlessBindingSet``, ``Options::bindlessBindingStartSlot`` and
``Options::bindlessBindingLayout``.

Backend ABI
===========

HLSL 6
    Preserves ``ResourceDescriptorHeap``, ``SamplerDescriptorHeap``, and
    ``NonUniformResourceIndex`` for compilation by a Shader Model 6.6 compiler.

Vulkan GLSL
    Creates one runtime descriptor array for every distinct typed heap view,
    emits ``nonuniformEXT`` for non-uniform indices, and requires
    ``GL_EXT_nonuniform_qualifier``. Generated bindings use the configured set
    and the slots of the selected layout.

PSSL
    Lowers each heap to one buffer of native descriptors, regardless of the
    layout: the sampler heap at the start slot and the resource heap at the
    slot after it.

Reflection reports whether either source heap is used and lists every binding
generated by the selected backend, including its heap, binding class, set or
space, binding location, generated identifier, and exact resource or native
descriptor element type. HLSL output has heap-usage reflection but no generated
binding because its global heaps belong to the application's root-signature
ABI.
